# Workflow modes

## New interface or visual polish

Read [design-quality.md](design-quality.md), [aesthetic-judgment.md](aesthetic-judgment.md), and [aesthetic-signals.md](aesthetic-signals.md). For an interactive web or application surface, also read [interaction-quality.md](interaction-quality.md). Derive a coherent direction from the brief, judge it by durable visual relationships, then use dated generator fingerprints only to catch choices made from habit.

## Existing-product redesign

Read [redesign.md](redesign.md), [aesthetic-judgment.md](aesthetic-judgment.md), and [interaction-quality.md](interaction-quality.md) when the redesign changes or reimplements an interactive surface. Audit first, classify preservation constraints, and separate visual modernization from approved structural change. The redesign should improve the product's own visual logic rather than overwrite it with the agent's preferred style.

## Screenshot, mockup, or generated reference to code

Read [visual-reference.md](visual-reference.md) and [aesthetic-judgment.md](aesthetic-judgment.md). If the result is a live interactive interface rather than a static reproduction, also read [interaction-quality.md](interaction-quality.md). Treat the reference as evidence, extract its system, and compare rendered implementation against it. Preserve intentional irregularity when it is part of the reference rather than normalizing everything into a generic component system.

## Platform style profile

Load a platform-specific reference only when the user explicitly requests that language. Treat it as a profile layered over the same hierarchy, state, accessibility, interaction-quality, and verification rules; platform conventions do not replace aesthetic judgment.
